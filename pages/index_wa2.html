Landmarks in code

GameMaker’s homepage is a clear and useable website. However, when inspecting the source code, it does not fully reflect the clarity of the page. I found that the code uses semantic tags inconsistently. They use some of the main ones, like nav, footer etc. However, sections are barley used. When searching for sections at the different subpages, they were used 1 – 4 times per page. The same issue was for article. Where they linked tutorials, they used article tags. However, for blogs and article posting, they did not use them. This inconsistency can be problematic when it comes to accessibility. “Document landmarks are roles that help assistive technologies understand the role of a section and its relationship to other content on that page. Kalbag” (2017, 118). I also tested the page with reader view, which struggled finding content, and left out most things. The site is pretty useable and well made, however still has accessibility issues for people relying on assistive technology.

This inconsistent use of semantic tags can also be an issue for code readability. Where it can cause confusion when reading and understanding the code. I also found that indentations are not used effectively, and tags start and end at seemingly random places. Having to search where tags start, and end should not be the case and can make working with the page needlessly complicated.
